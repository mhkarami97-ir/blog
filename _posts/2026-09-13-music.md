**تئوری موسیقی برای برنامه‌نویس‌ها: درک موسیقی با منطق و کد (بخش اول)**

همیشه فکر می‌کردم تئوری موسیقی یک دنیای کاملاً حسی، انتزاعی و پر از قواعد عجیب و غریب است که هیچ ارتباطی با دنیای منطقی و صفر و یک ما برنامه‌نویس‌ها ندارد. اما وقتی عمیق‌تر به آن نگاه کردم، متوجه شدم که موسیقی در هسته خود چیزی جز ریاضیات، الگوها و فرکانس‌ها نیست. در واقع، موسیقی یک سیستم کاملاً منطقی است که می‌توان آن را با کد تفسیر و تولید کرد.

در این سری مقالات، قرار است تئوری موسیقی را از لنز یک برنامه‌نویس بررسی کنیم. نیازی نیست هیچ ساز موسیقی بلد باشید؛ فقط کافی است کمی جاوا اسکریپت بدانید!

### صدا چیست؟ همه چیز فرکانس است

صدا در فیزیک چیزی جز لرزش مولکول‌های هوا نیست. وقتی یک سیم گیتار را به صدا درمی‌آورید، آن سیم در هوا ارتعاش ایجاد می‌کند و این ارتعاشات به شکل موج به پرده گوش ما می‌رسند.

مهم‌ترین ویژگی این موج برای ما، **فرکانس** (Frequency) است. فرکانس یعنی این موج در هر یک ثانیه چند بار تکرار می‌شود و واحد اندازه‌گیری آن **هرتز (Hz)** است. گوش انسان توانایی شنیدن فرکانس‌های بین ۲۰ تا ۲۰,۰۰۰ هرتز را دارد.

در دنیای موسیقی، ما به جای استفاده از اعداد فرکانس، به آن‌ها نام‌هایی اختصاص داده‌ایم که به آن‌ها **نت (Note)** می‌گوییم.

### نت مبنا: A4 (نت لا)

برای اینکه تمام سازهای دنیا بتوانند با هم هم‌نوازی کنند، به یک استاندارد جهانی نیاز داشتیم. این استاندارد روی نت **A (لا)** در اکتاو چهارم پیانو تنظیم شده است.
فرکانس دقیق این نت استاندارد چقدر است؟ دقیقاً **۴۴۰ هرتز**.

بیایید با استفاده از `Web Audio API` در مرورگر، این نت را با چند خط کد تولید کنیم:

```javascript
// ایجاد کانتکست صدا در مرورگر
const audioCtx = new (window.AudioContext || window.webkitAudioContext)();

// ایجاد یک تولیدکننده موج
const oscillator = audioCtx.createOscillator();

// تنظیم شکل موج روی سینوسی (ساده‌ترین نوع موج صوتی)
oscillator.type = 'sine';

// تنظیم فرکانس روی ۴۴۰ هرتز (نت A4)
oscillator.frequency.value = 440; 

// اتصال به خروجی سیستم (اسپیکرها)
oscillator.connect(audioCtx.destination);

// پخش صدا!
oscillator.start();

// قطع صدا بعد از 2 ثانیه
setTimeout(() => {
  oscillator.stop();
}, 2000);

```

اگر این کد را در کنسول مرورگر خود اجرا کنید، صدای خالص نت لا (A) را خواهید شنید.

### مفهوم اکتاو (Octave) و ضرب در دو

حالا بیایید کمی ریاضیات وارد کار کنیم. اگر فرکانس ۴۴۰ هرتز را دقیقاً ضرب در ۲ کنیم، به عدد ۸۸۰ هرتز می‌رسیم.
در موسیقی، به این فرکانس جدید هم نت **A (لا)** می‌گویند، با این تفاوت که صدای آن زیرتر (زیر و بمی بالاتر) است. به این فاصله بین یک نت و دو برابر شدن فرکانس آن، یک **اکتاو (Octave)** گفته می‌شود.

* فرکانس `220 Hz` = نت A در یک اکتاو پایین‌تر (A3)
* فرکانس `440 Hz` = نت A مبنا (A4)
* فرکانس `880 Hz` = نت A در یک اکتاو بالاتر (A5)

### محاسبه جادویی ۱۲ نت

در موسیقی غربی، یک اکتاو (مثلاً از A4 تا A5) به **۱۲ قسمت مساوی** تقسیم شده است. به هر کدام از این قسمت‌ها یک "نیم‌پرده" (Semitone) می‌گویند.

اما این تقسیم‌بندی خطی نیست (یعنی نمی‌توانیم اختلاف ۴۴۰ را بر ۱۲ تقسیم کنیم). گوش انسان تغییرات صدا را به صورت **لگاریتمی** درک می‌کند. بنابراین، برای پیدا کردن فرکانس هر نتِ بعدی، باید فرکانس فعلی را در یک عدد ثابت ضرب کنیم.
چون بعد از ۱۲ مرحله ضرب شدن، فرکانس باید دقیقاً ۲ برابر شود، آن عدد ثابت برابر است با **ریشه دوازدهم عدد ۲** (دقیقاً `1.059463`).

ریاضیات آن در جاوا اسکریپت به این شکل پیاده‌سازی می‌شود:

```javascript
/**
 * محاسبه فرکانس هر نت بر اساس فاصله آن از نت مبنا (A4)
 * @param {number} semitones - تعداد نیم‌پرده فاصله از A4 (می‌تواند منفی باشد)
 * @returns {number} فرکانس نت محاسبه شده
 */
function getNoteFrequency(semitones) {
  const A4 = 440;
  // فرمول: فرکانس مبنا ضربدر (2 به توان فاصله تقسیم بر 12)
  return A4 * Math.pow(2, semitones / 12);
}

// فرکانس خود نت لا (فاصله 0)
console.log(getNoteFrequency(0)); // 440

// فرکانس یک نیم‌پرده بالاتر (A# یا Bb)
console.log(getNoteFrequency(1)); // 466.16

// فرکانس یک اکتاو بالاتر (12 نیم‌پرده)
console.log(getNoteFrequency(12)); // 880

```

با همین یک تابع ساده، ما توانستیم کل کیبورد یک پیانو را با ریاضیات و کد شبیه‌سازی کنیم! تمام کلیدهای پیانو با همین فرمول ریاضی کار می‌کنند.

**تئوری موسیقی برای برنامه‌نویس‌ها (بخش دوم): رفع باگ‌های صوتی، هارمونیک‌ها و جادوی نسبت‌ها**

در بخش قبلی دیدیم که چگونه با استفاده از مرورگر و تولید یک موج سینوسی با فرکانس مشخص (مثل ۴۴۰ هرتز)، اولین نت موسیقی خود را خلق کردیم و با منطق ریاضیاتی فواصل نت‌ها در سیستم ۱۲ قسمتی آشنا شدیم. اما اگر با دقت به صدایی که تولید کردیم گوش داده باشید، احتمالاً متوجه یک مشکل کوچک شده‌اید.

### چرا در انتهای نت صدای «تق» (Click) شنیده می‌شود؟

کامپیوتر دقیقاً همان کاری را کرد که به آن گفتیم. وقتی زمان اجرای نت تمام می‌شود، تولید موج به صورت ناگهانی متوقف می‌گردد. در این لحظه، مخروط اسپیکر که در حال لرزش و جابجایی هوا بوده، در هر نقطه‌ای از دامنه موج که باشد، به صورت آنی به حالت اولیه خود (صفر) برمی‌گردد. این تغییر فشار ناگهانی، در گوش ما به شکل یک صدای «تق» یا کلیک ترجمه می‌شود. این یک باگ نرم‌افزاری نیست، بلکه فیزیک خالص است.

برای رفع این مشکل در معماری صدایمان، به متغیر دومی نیاز داریم که در طول زمان تغییر کند: متغیری برای کنترل **حجم صدا (Volume)**. در دنیای موسیقی به شکل تغییرات حجم صدا در طول زمان، **انولوپ (Envelope)** می‌گویند.

مدل استاندارد برای این کار **ADSR** نام دارد که مخفف *Attack* (زمان رسیدن به حداکثر صدا)، *Decay* (افت اولیه)، *Sustain* (میزان ماندگاری تا زمان رهاسازی) و *Release* (زمان محو شدن صدا) است.

بیایید کد قبلی را بر اساس اصول شی‌ءگرایی (OOP) و Clean Code بازنویسی کنیم و یک لایه `GainNode` (برای مدیریت Volume) به آن اضافه کنیم:

```javascript
/**
 * کلاس AudioSynthesizer برای مدیریت و تولید سینت‌سایزر صوتی
 * طراحی شده بر اساس الگوهای Clean Code برای استفاده مجدد و توسعه‌پذیری
 */
class AudioSynthesizer {
    constructor() {
        // استفاده از AudioContext استاندارد
        this.ctx = new (window.AudioContext || window.webkitAudioContext)();
        this.masterOut = this.ctx.destination;
    }

    /**
     * پخش یک نت با فرکانس، زمان و شکل موج مشخص همراه با Envelope
     * @param {number} freq - فرکانس نت به هرتز
     * @param {number} startOffset - تاخیر در شروع به ثانیه
     * @param {number} length - طول مدت پخش نت
     * @param {string} waveType - نوع موج (sine, square, triangle, sawtooth)
     */
    playNote(freq, startOffset = 0, length = 0.5, waveType = "sine") {
        const t = this.ctx.currentTime + startOffset;
        
        const oscillator = this.ctx.createOscillator();
        const envelope = this.ctx.createGain();

        oscillator.type = waveType;
        oscillator.frequency.value = freq;

        // پیاده‌سازی Envelope (حذف صدای تق)
        // Attack: رسیدن نرم صدا به 0.3 در 10 میلی‌ثانیه
        envelope.gain.setValueAtTime(0, t);
        envelope.gain.linearRampToValueAtTime(0.3, t + 0.01);
        
        // Decay/Release: محو شدن نمایی صدا تا نزدیک به صفر در انتهای طول نت
        envelope.gain.exponentialRampToValueAtTime(0.001, t + length);

        // اتصال گره‌ها: Oscillator -> Envelope -> Master Output
        oscillator.connect(envelope).connect(this.masterOut);

        oscillator.start(t);
        oscillator.stop(t + length);
    }
}

// نمونه‌سازی و استفاده
const synth = new AudioSynthesizer();
synth.playNote(440); // اکنون صدای نت A کاملاً نرم و بدون باگ شنیده می‌شود

```

ده میلی‌ثانیه برای محو شدن (Fade in) و سپس یک افت تدریجی. همین تغییر ساده، تفاوت بین یک «بوق آزمایشگاهی» و صدایی است که گوش شما حاضر است به عنوان موسیقی آن را بپذیرد. اگر فاز Attack را از 10 میلی‌ثانیه به نیم ثانیه افزایش دهید، نت دیگر شبیه به ضربه زدن روی کلاویه پیانو نیست، بلکه شبیه به کشیدن آرشه روی ویولن به نظر می‌رسد؛ در حالی که فرکانس حتی یک هرتز هم تغییر نکرده است!

### رنگ صدا (Timbre): فرکانس‌هایی که شما درخواست نکردید

موج سینوسی (Sine wave) تنها شامل یک فرکانس خالص است؛ به همین دلیل است که صدای آن شبیه به تست‌های شنوایی‌سنجی است و هیچ شباهتی به سازهای واقعی ندارد.
وقتی شما سیم گیتاری را که روی ۴۴۰ هرتز کوک شده به صدا درمی‌آورید، سیم فقط ۴۴۰ بار در ثانیه نمی‌لرزد. سیم به طور همزمان در نیمه‌ها، یک‌سوم‌ها و یک‌چهارم‌های طول خود نیز در حال ارتعاش است.

این یعنی علاوه بر فرکانس پایه ۴۴۰، ساز شما فرکانس‌های ۸۸۰، ۱۳۲۰، ۱۷۶۰ و الی آخر را نیز **به صورت همزمان** تولید می‌کند. به این پشته فرکانس‌ها، **سری هارمونیک (Harmonic Series)** می‌گویند. فرکانس اصلی همان نت پایه است و بقیه مضاربی صحیح از آن هستند (`فرکانس پایه * 1, 2, 3, 4 ...`).

اینکه هر کدام از این هارمونیک‌ها نسبت به یکدیگر چقدر بلند یا ضعیف هستند، دستورالعملی است که باعث می‌شود صدای ویولن از ترومپت متمایز شود. به این پدیده **رنگ صدا (Timbre)** می‌گویند.

مرورگرها به صورت پیش‌فرض ۴ دستورالعمل موجی آماده را در اختیار ما قرار می‌دهند:

```javascript
const mySynth = new AudioSynthesizer();
const waveforms = ["sine", "triangle", "square", "sawtooth"];

// پخش یک نت یکسان (220 هرتز) با 4 رنگ صدای کاملاً متفاوت
waveforms.forEach((type, index) => {
    mySynth.playNote(220, index * 0.7, 0.6, type);
});

```

فرکانس همه آن‌ها ۲۲۰ هرتز است، اما شخصیت‌های متفاوتی دارند. موج مربعی (`square`) فقط هارمونیک‌های فرد را دارد، به همین دلیل صدای توخالی و کمی الکترونیکی می‌دهد. موج دندان‌اره‌ای (`sawtooth`) تمام هارمونیک‌ها را دارد و صدایی خشن و وزوزمانند تولید می‌کند.

### جادوی نسبت‌های ساده (چرا بعضی نت‌ها فالش به نظر نمی‌رسند؟)

اگر به بخش اول برگردیم، به خاطر دارید که فواصل فرکانسی ماهیت لگاریتمی (ضرب‌شونده) دارند و نه خطی (جمع‌شونده). دو برابر کردن فرکانس، ما را به همان نت در اکتاو بالاتر می‌رساند. اما فاصله فرکانسیِ بین این اکتاو را چگونه باید تقسیم کنیم؟

ساده‌ترین پاسخ این است که فواصل را به صورت مساوی تقسیم کنیم و تمام. اما هیچ‌کس در تاریخ موسیقی این کار را نکرد! دلیلش این است که گوش ما تمام جفت‌فرکانس‌ها را به یک شکل تجربه نمی‌کند. برخی از ترکیب‌ها به نظر می‌رسد در کمال آرامش در کنار هم نشسته‌اند (Consonance) و برخی دیگر شبیه به یک تصادف وحشتناک هستند (Dissonance).

کد زیر را بررسی کنید که نت ۲۲۰ هرتز را در کنار فرکانس‌هایی با نسبت‌های ریاضی مختلف پخش می‌کند:

```javascript
const ratioTestSynth = new AudioSynthesizer();
const baseFreq = 220;

// آرایه‌ای از نسبت‌های ریاضی معروف در موسیقی
const intervals = [
    { label: "2/1 (Octave)", ratio: 2 },
    { label: "3/2 (Perfect Fifth)", ratio: 3 / 2 },
    { label: "4/3 (Perfect Fourth)", ratio: 4 / 3 },
    { label: "5/4 (Major Third)", ratio: 5 / 4 },
    { label: "16/15 (Semitone)", ratio: 16 / 15 },
    { label: "√2 (The awkward one - Tritone)", ratio: Math.SQRT2 }
];

intervals.forEach((interval, index) => {
    const timeOffset = index * 1.5;
    
    // پخش نت پایه و نتِ دارای نسبت ریاضی به صورت همزمان برای تشکیل آکورد/فاصله
    ratioTestSynth.playNote(baseFreq, timeOffset, 1.2);
    ratioTestSynth.playNote(baseFreq * interval.ratio, timeOffset, 1.2);
    
    console.log(`${interval.label} -> ${(baseFreq * interval.ratio).toFixed(2)}Hz`);
});

```

اگر این نت‌ها را با هم بشنوید، الگوی پنهان موسیقی بلافاصله خودش را نشان می‌دهد: **هرچه کسر نسبت ساده‌تر باشد، صدای تولید شده دلنشین‌تر است.**
نسبت `2/1` اکتاو است، `3/2` فاصله پنجم، `4/3` فاصله چهارم. اینها شبیه به آکورد به نظر می‌رسند. اما وقتی به نسبت `16/15` می‌رسید، صدا شبیه به بحث و دعوای دو نت با هم است و نسبت رادیکال ۲ (`√2`) مانند آژیر دزدگیر ماشین به نظر می‌رسد!

**دلیل فیزیکی این اتفاق چیست؟**
دو دلیل علمی برای آن وجود دارد:

1. **اشتراک در هارمونیک‌ها:** وقتی فرکانس‌های ۲۲۰ و ۳۳۰ (نسبت ۳:۲) را با هم می‌نوازید، هارمونیک‌های ۲۲۰ شامل (۲۲۰، ۴۴۰، ۶۶۰، ۸۸۰) است و هارمونیک‌های ۳۳۰ شامل (۳۳۰، ۶۶۰، ۹۹۰). آن‌ها در هارمونیک **۶۶۰ هرتز** دقیقاً روی هم می‌افتند (اشتراک دارند). این دو نت، دو صدای کاملاً مجزا نیستند، بلکه دو پشته فرکانسی هستند که یکدیگر را تقویت می‌کنند. اما در نسبت رادیکال ۲، هیچ‌کدام از هارمونیک‌ها هرگز روی هم منطبق نمی‌شوند.
2. **پدیده ضربان (Beating):** وقتی دو فرکانس به هم نزدیک باشند اما دقیقاً یکسان نباشند، فاز امواج آن‌ها مدام با هم تداخل می‌کند و شما صدای "لرزش" یا پالس حجم صدا را می‌شنوید. سرعت این لرزش دقیقاً برابر با اختلاف فرکانس آن‌هاست. در کسرهای پیچیده یا اعداد گنگ (مثل رادیکال ۲)، هزاران لرزش و ضربان کوچک بین هارمونیک‌های دو صدا شکل می‌گیرد که مغز آن را به عنوان یک صدای «ناهنجار» یا Dissonance تفسیر می‌کند. گوش ما در موسیقی، تنها به دنبال یافتن سریع الگوهای تکرارشونده است.

### روی هم چیدن پنجم‌ها (Stacking Fifths) و باگی که نمی‌توانید فیکس کنید

اکنون که می‌دانیم نسبت‌های ساده چقدر جادویی هستند، بیایید یک سیستم کامل موسیقیایی بر اساس آن‌ها بسازیم. بعد از اکتاو (۲/۱)، تمیزترین نسبت در فیزیک صوت، نسبت **۳/۲ (فاصله پنجم)** است.
چه می‌شود اگر سعی کنیم الفبای موسیقی را فقط و فقط با ضرب کردن فرکانس‌ها در ۳/۲ و محدود کردن آن‌ها در یک اکتاو (با تقسیم بر ۲) بسازیم؟

این دقیقاً همان روشی است که فیثاغورث در یونان باستان پیشنهاد داد. بیایید این الگوریتم را پیاده‌سازی کنیم:

```javascript
const pythagoreanSynth = new AudioSynthesizer();
let currentFreq = 220;
const pythagoreanNotes = [220];

// سعی می‌کنیم 12 نت با استفاده از قانون پنجم‌ها (ضربدر 3/2) بسازیم
for (let i = 0; i < 12; i++) {
    currentFreq = (currentFreq * 3) / 2;
    
    // اگر فرکانس از مرز اکتاو (440) عبور کرد، آن را نصف می‌کنیم تا در همان اکتاو بماند
    while (currentFreq >= 440) {
        currentFreq = currentFreq / 2;
    }
    
    pythagoreanNotes.push(currentFreq);
    console.log(`Fifth ${i + 1}: ${currentFreq.toFixed(3)} Hz`);
}

// مرتب‌سازی نت‌ها از بم به زیر و پخش آن‌ها
pythagoreanNotes.sort((a, b) => a - b).forEach((freq, index) => {
    pythagoreanSynth.playNote(freq, index * 0.25, 0.3);
});

```

این روش در ابتدا عالی کار می‌کند و ما در نهایت به ۱۲ نت مختلف می‌رسیم. اما... در اینجا یک باگ ریاضی نهفته است که فیزیک صوت هرگز اجازه حل آن را به ما نمی‌دهد! در بخش بعدی خواهیم دید که چرا این روشِ بی‌نقص ریاضی در عمل با شکست مواجه می‌شود و چگونه برنامه‌نویسانِ دنیای موسیقی، این باگ را با مفهوم مهمی به نام "Equal Temperament" دور زدند.

**تئوری موسیقی برای برنامه‌نویس‌ها (بخش سوم و پایانی): باگ فیثاغورث، گام‌ها و خلق آکوردها**

در بخش قبلی دیدیم که چگونه با ضرب کردن فرکانس‌ها در نسبت جادویی و گوش‌نواز ۳/۲ (فاصله پنجم)، سعی کردیم تمام ۱۲ نت موسیقی را بسازیم. این روش که به سیستم کوک فیثاغورثی معروف است، روی کاغذ فوق‌العاده به نظر می‌رسد، اما در عمل ما را با یک باگ فیزیکی غیرقابل‌حل مواجه می‌کند.

### باگی در سیستم عامل فیزیک: کمای فیثاغورثی

مشکل اینجاست که ریاضیاتِ پشت «فاصله‌های پنجم» و «اکتاوها» هرگز دقیقاً روی هم منطبق نمی‌شوند.
اگر شما از یک فرکانس پایه شروع کنید و ۱۲ بار متوالی فاصله پنجم را طی کنید (یعنی فرکانس را ۱۲ بار در $3/2$ ضرب کنید)، و در مقابل، از همان فرکانس پایه ۷ اکتاو بالا بروید (یعنی فرکانس را ۷ بار در $2$ ضرب کنید)، انتظار دارید در نهایت به یک نت واحد برسید. اما بیایید حساب کنیم:

* مسیر پنجم‌ها: $(3/2)^{12} \approx 129.74$
* مسیر اکتاوها: $2^7 = 128$

این دو عدد برابر نیستند! این اختلاف ریاضی که به «کمای فیثاغورثی» معروف است، به این معناست که اگر سازتان را با نسبت‌های کامل و بی‌نقص فیزیکی کوک کنید، وقتی از نت‌های اولیه دور می‌شوید و به کلیدهای دیگر می‌روید، سازتان کاملاً فالش و ناهنجار صدا خواهد داد. به زبان برنامه‌نویسی، این یک Memory Leak در دنیای فرکانس‌هاست که با هر تغییر گام، بیشتر خودش را نشان می‌دهد.

### راه‌حل: Equal Temperament (توزیع مساوی خطا)

چگونه این باگ را حل کنیم؟ با یک هک مهندسی درخشان. ما نسبت‌های کامل و بی‌نقص فیزیکی (مثل ۳/۲) را فدا می‌کنیم و در عوض، این خطای کوچک را به طور مساوی بین تمام ۱۲ نت اکتاو تقسیم می‌کنیم.
به جای استفاده از کسر خالص ۳/۲، ما اکتاو را به ۱۲ قسمتِ لگاریتمیِ کاملاً مساوی تقسیم می‌کنیم (همان فرمول $2^{1/12}$ که در بخش اول نوشتیم).

با این سیستم که **Equal Temperament (اعتدال مساوی)** نامیده می‌شود، فاصله پنجم به جای $1.5$ دقیق، برابر با $1.498$ خواهد بود. این فاصله به قدری به واقعیت نزدیک است که مغز ما به راحتی آن را می‌پذیرد. حالا می‌توانیم در هر گامی بنوازیم بدون اینکه نگران فالش شدن صدا باشیم. تمام موسیقی‌های مدرن از همین هک استفاده می‌کنند.

### گام‌ها (Scales): محدود کردن انتخاب‌ها برای خلق الگو

دسترسی همزمان به ۱۲ نت، مثل داشتن یک پالت رنگی با بی‌نهایت رنگ است؛ اگر همه را با هم ترکیب کنید، نتیجه یک نویز آزاردهنده یا رنگی گلی و کثیف می‌شود. برای خلق یک موسیقی معنی‌دار، باید محدودیت ایجاد کنیم.
**گام (Scale)** صرفاً زیرمجموعه‌ای از این ۱۲ نت است که یک حس خاص (مثلاً شاد، غمگین، مرموز) را القا می‌کند.

مشهورترین گام در موسیقی غربی، **گام ماژور (Major Scale)** است. این گام از ۷ نت تشکیل شده و الگوی فواصل آن بین نت‌ها به این شکل است:
**۲ پرده، ۲ پرده، ۱ نیم‌پرده، ۲ پرده، ۲ پرده، ۲ پرده، ۱ نیم‌پرده.**

بیایید این منطق را با استفاده از اصول OOP و یک معماری تمیز به کد تبدیل کنیم:

```javascript
class MusicTheory {
    // نسبت طلایی اعتدال مساوی برای یک نیم‌پرده
    static SEMITONE_RATIO = Math.pow(2, 1 / 12);

    /**
     * محاسبه فرکانس یک نت بر اساس فاصله آن از نت ریشه
     */
    static getFrequency(rootFreq, semitones) {
        return rootFreq * Math.pow(this.SEMITONE_RATIO, semitones);
    }

    /**
     * تولید یک گام کامل بر اساس فرکانس پایه و الگوی فواصل
     * @param {number} rootFreq - فرکانس نت پایه (مثلاً 220 برای A3)
     * @param {number[]} intervals - الگوی فواصل به نیم‌پرده
     * @returns {number[]} آرایه‌ای از فرکانس‌های گام
     */
    static generateScale(rootFreq, intervals) {
        const scale = [rootFreq];
        let currentFreq = rootFreq;

        for (const interval of intervals) {
            currentFreq = this.getFrequency(currentFreq, interval);
            scale.push(currentFreq);
        }
        
        return scale;
    }
}

// الگوی گام ماژور: 2, 2, 1, 2, 2, 2, 1 (پرده = 2 نیم‌پرده)
const majorPattern = [2, 2, 1, 2, 2, 2, 1];

// تولید گام لا ماژور (A Major) از فرکانس 220Hz
const aMajorScale = MusicTheory.generateScale(220, majorPattern);
console.log(aMajorScale);

```

### آکوردها (Chords): پخش موازی نت‌ها

حالا که مجموعه‌ای از نت‌های هماهنگ (گام ماژور) را داریم، اگر چند نت از این مجموعه را به صورت همزمان پخش کنیم چه می‌شود؟ به این کار **آکورد** می‌گویند.
پایه‌ای‌ترین نوع آکورد، «تِریاد» (Triad) نام دارد که از ۳ نت تشکیل شده است. فرمول ساخت آن ساده است: یک نت از گام را انتخاب کنید، نت بعدی گام را جا بیندازید، نت بعدی را بردارید، یکی را جا بیندازید و سومی را بردارید. (اندیس‌های `0, 2, 4` از آرایه گام).

```javascript
/**
 * استخراج یک آکورد سه‌صدایی (Triad) از یک گام مشخص
 * @param {number[]} scale - آرایه فرکانس‌های گام
 * @param {number} rootIndex - اندیس نت پایه آکورد در گام
 */
function getTriadChord(scale, rootIndex) {
    // برای سادگی، فرض می‌کنیم گام ما به اندازه کافی در اکتاوهای بالاتر بسط داده شده است
    // در یک سیستم واقعی باید آرایه را به صورت چرخشی (Modulo) مدیریت کنیم
    return [
        scale[rootIndex],
        scale[rootIndex + 2],
        scale[rootIndex + 4]
    ];
}

// استخراج آکورد درجه اول (آکورد ریشه)
const rootChord = getTriadChord(aMajorScale, 0); 

```

### توالی آکوردها (Chord Progressions): خلق حرکت در موسیقی

موسیقی صرفاً یک آکورد ایستا نیست؛ موسیقی هنر حرکت از یک نقطه به نقطه دیگر و ایجاد کشش و رهایی است. ما آکوردها را پشت سر هم می‌نوازیم تا یک **توالی (Progression)** بسازیم.

برای اینکه سینت‌سایزر صوتی ما (که در بخش دوم ساختیم) بتواند این توالی را پخش کند، کافیست از زمان‌بندیِ دقیقِ Web Audio API استفاده کنیم. نیازی به `setTimeout` نیست، زیرا زمان‌بندی مرورگر برای صدا بسیار دقیق‌تر و بهینه‌تر از حلقه رویداد (Event Loop) جاوا اسکریپت است.

بیایید معروف‌ترین توالی آکورد در موسیقی پاپ (I - V - vi - IV) را برنامه‌نویسی کنیم:

```javascript
// بسط دادن گام ماژور به دو اکتاو برای جلوگیری از خطای Out of Bounds
const extendedMajorPattern = [...majorPattern, ...majorPattern];
const fullScale = MusicTheory.generateScale(220, extendedMajorPattern);

// توالی آکورد معروف پاپ: درجه 1، درجه 5، درجه 6، درجه 4
const progressionIndices = [0, 4, 5, 3]; 
const synth = new AudioSynthesizer(); // کلاسی که در بخش دوم توسعه دادیم
const now = synth.ctx.currentTime;
const chordDuration = 1.0; // هر آکورد یک ثانیه طول می‌کشد

progressionIndices.forEach((scaleIndex, sequenceStep) => {
    // استخراج نت‌های آکورد
    const chordFrequencies = getTriadChord(fullScale, scaleIndex);
    
    // محاسبه زمان شروع این آکورد در توالی
    const startTime = sequenceStep * chordDuration;

    // پخش همزمان 3 نت آکورد
    chordFrequencies.forEach(freq => {
        synth.playNote(freq, startTime, chordDuration);
    });
});

```

کد بالا را اجرا کنید. شما در حال شنیدن ساختار پایه‌ای صدها آهنگ موفق پاپ هستید، از بیتلز گرفته تا اد شیرن. تمام این‌ها بدون لمس هیچ ساز فیزیکی و صرفاً با استفاده از ریاضیات، آرایه‌ها و حلقه‌ها تولید شد.

### سخن پایانی: نت‌نویسی سنتی صرفاً یک UI است!

وقتی موسیقی را از پایین‌ترین لایه‌های معماری‌اش (فرکانس و ریاضیات) درک می‌کنید، متوجه می‌شوید که نت‌نویسی سنتی (پنج‌خط حامل، کلید سل، علائم دیز و بمل) در واقع چیست. نت‌نویسی سنتی چیزی جز یک **رابط کاربری (UI)** قدیمی و استاندارد برای انتزاع و پنهان کردن پیچیدگی‌های ریاضی این سیستم نیست.

درست همانطور که ما در برنامه‌نویسی برای ارتباط با سخت‌افزار از زبان‌های سطح بالا استفاده می‌کنیم، موسیقیدانان هم برای ارتباط با سیستم پیچیده‌ی فرکانس‌ها و نسبت‌ها، از این نمادهای گرافیکی استفاده می‌کنند.
